# Documentation review

Reviewed 2026-09-30 against commit `6339747b7e7b51df74fab518001281322510cac5` (v0.15.0 plus deletion of the previous archive).

The active documentation should shrink substantially. Most removable material is incremental extraction history, resolved reviews and retired optimizer experiments. Current user guides and several architecture indexes need correction because they still describe unfinished migrations that have since shipped. Keep the semantic and byte-format contracts even where their original implementation plan is complete.

The user approved the 188 retirement recommendations: 104 redundant documents are deleted and 84 historical documents are moved to `docs/archive/`. The 73 Update and 39 Keep documents stay active. The README update is now complete; updates to the other 72 documents remain pending. The findings and counts below describe the original review baseline.

## What the implementation says today

The Rust/Id-message migration is complete in the current source layout. `birnam-runtime`, the native IdApi tables and the old `src/id/*` authored-source layout are removed. Functional owners and `modules/` now carry the implementation. Host, Image, project execution, REPL/LSP, workers and generation publication/rollback have been reconnected. Check current contracts at [rust/birnam-host/README.md](../rust/birnam-host/README.md), [rust/birnam-codegen-runtime/README.md](../rust/birnam-codegen-runtime/README.md), [rust/birnam-image/README.md](../rust/birnam-image/README.md) and [rust/birnam-execution/README.md](../rust/birnam-execution/README.md).

That completion does not finish the longer-term Birnam-authored runtime/compiler objective in [docs/design/81-toward-a-birnam-implementation.md](design/81-toward-a-birnam-implementation.md), future thread/channel/I/O work in [docs/design/80-concurrency-domains-and-structured-tasks.md](design/80-concurrency-domains-and-structured-tasks.md), Map deletion in [docs/design/70-persistent-map-deletion.md](design/70-persistent-map-deletion.md), or scalable sorting/String ordering in [docs/design/73-scalable-ordering-contract.md](design/73-scalable-ordering-contract.md). The Map source still rebuilds removal using ordinary `=`; Vector sorting still uses insertion sort. The sorting design gate is accepted, while implementation stories remain open.

The current optimizer surface is narrower than the old 74-series experiments. Clone-elision and numeric-predicate contracts remain relevant. Removed aggregate-Runtime accounting, journals and deferred/prepaid identity machinery should not be reintroduced by retaining their old operational plans.

These conclusions come from document review, current code/owner contracts, workspace and source-path checks, the changelog, validation scripts and `.beads/issues.jsonl`. No runtime suite or fresh release qualification was run for this review. Dated acceptance evidence remains evidence for its recorded scope.
